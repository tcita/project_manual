#### **1. 证明策略**

为证明优化问题 `CARD_GAME_OPT` 是 NP-hard 的，我们将采用**图灵规约 (Turing Reduction)** 的方法，从一个已知的 NP-complete 问题——**子集和问题 (Subset Sum Problem)**——进行规约。

证明的核心逻辑遵循**反证法**：
首先，我们假设 `CARD_GAME_OPT` **不是** NP-hard 的，即存在一个能解决它的多项式时间算法。然后，我们将展示如何利用这个假想的算法作为预言机（Oracle），来设计**另一个**多项式时间算法，从而使用此算法解决子集和问题。

如果以上逻辑成立，则意味着一个 NP-complete 问题可以在多项式时间内被解决，这将导出 P=NP 的结论。这与计算复杂性理论中 P≠NP 的基本假设相矛盾，因此我们最初的假设必然是错误的。

#### **2. 相关问题定义**

* **子集和问题 (Subset Sum Problem)**
    * **输入**：一个由 `n` 个**互异的**（distinct）正整数构成的**集合** `S = {s₁, s₂, ..., sₙ}` 和一个目标整数 `T`。
    * **问题**：是否存在 `S` 的一个子集 `S' ⊆ S`，使得 `S'` 中所有元素的和恰好等于 `T`？
    * **复杂度**：此问题是经典的 NP-complete 问题[1]。我们特指其处理互异整数集合的形式，以确保规约的有效性。

* **卡牌游戏优化问题 (CARD_GAME_OPT)**
    * **输入**：两个卡牌列表 `A` 和 `B`。
    * **问题**：找到一个出牌策略，使得最终获得的总得分**最大化**，并返回这个最大分值。

#### **3. 规约证明**

**第一步：反证假设**

假设 `CARD_GAME_OPT` 存在一个多项式时间解法，我们称这个假想的算法为 `Solve_OPT`。我们可以将其视为一个预言机 `O`，它能在多项式时间内完成 `O(A, B) = max_score` 的计算。

**第二步：设计用于解决子集和问题的新算法**

我们设计一个新算法，命名为 `SubsetSumSolver`，它以一个子集和问题的实例 `(S, T)` 作为输入。此算法通过调用预言机 `O` 来判断问题的解是否存在。

**A. 预言机能力封装**

`SubsetSumSolver` 算法需要将其想要查询的数学问题“翻译”成预言机 `O` 能理解的游戏问题,因为我们要利用此预言机 `O`来解决子集和问题。为此，算法内部实现了一个核心函数 `MaxSubsetSum(S_sub)` 。

* **函数 `MaxSubsetSum(S_sub)` 的操作流程：**
    1.  该函数接收 `S_sub` 作为参数,`S_sub`⊂ `S`。
    2.  根据该参数，函数程序化可以地构造*一个游戏实例 `I = (A=[X], B=[X] + S_sub)`。
        其中 X 是一个预先选定的、大于 Sum(S) 的足够大的整数。

     >*构造方法比如:对于任意的S,我们都可以通过计算 S 中所有元素的和并加1来得到X，即 X = Sum(S) + 1.
     >然后构造 A=[ X ] 和 B=[ X ] + S_sub 这样的构造符合卡牌游戏的规定,并且对于任意的S显然成立
    

    3.  函数将构造出的实例 `I` 传递给预言机 `O`，并获取返回值 `max_score`。
    4.  函数计算并返回 `max_score - 2X`。

<!-- MaxSubsetSum就是一个求和吗?那么和子集和有什么关系 -->
* **函数能力分析：**
    由于 `S` 中元素互异且 `X` 值极大，得分的唯一途径是匹配两张 `X` 牌,且根据游戏规则,卡牌游戏最大得分`max_score`明显是`sum(S_sub) + 2X` 。因此,由于S_sub互异,`max_score - 2X` 的结果恰好是输入集合 `S_sub` 的最大子集和（即 `S_sub` 中所有元素之和）。由于构造实例、调用预言机 `O` 和减法运算都是多项式时间的，所以 `MaxSubsetSum` 函数本身也是多项式时间的。

**B. `SubsetSumSolver` 算法主体**

该算法利用其内部函数 `MaxSubsetSum` 来判断是否存在和为 `T` 的子集。

* **算法执行流程 `SubsetSumSolver(S, T)`：**
    1.  **初始判断**：若 `T < 0` 或 `T > MaxSubsetSum(S)`，则解显然不存在，算法返回“否”。
    2.  **构造性求解**：
        a. 初始化目标和 `T_rem = T`。
        b. 创建 `S` 的一个副本 `S_rem` 作为待考察元素的集合，并按从大到小的顺序排列。
        c. 遍历 `S` 中的每一个元素 `sᵢ`：
            i.  从 `S_rem` 中移除 `sᵢ`。
            ii. 判断是否应该将 `sᵢ` 加入最终的解：
                * 如果 `sᵢ <= T_rem`，
                且 `T_rem - sᵢ <= MaxSubsetSum(S_rem)`(如果将sᵢ加入解的集合，那么代表在数字上无法凑齐T)
                
                这意味着如果选取 `sᵢ`，剩余的目标和 `T_rem - sᵢ` **有可能**被剩下的元素 `S_rem` 凑齐。算法做出决策，将 `sᵢ` 视为解的一部分，并更新 `T_rem = T_rem - sᵢ`。
    3.  **返回结果**：在遍历完所有元素后，如果 `T_rem` 恰好等于 `0`，则意味着算法成功地找到了一组元素`S_solution`的组合，其和为 `T`。算法返回“是”。否则，返回“否”。

该判定算法的完全正确性 (Total Correctness) 包含：

    A. 终止性 (Termination)：算法总能在有限步骤内停机。   
    B. 可靠性 (Soundness)：算法返回“是”时，问题确实有解。
    C. 完备性 (Completeness)：问题有解时，算法一定会返回“是”。

终止性显然成立,因为算法遍历S后就会终止



#### **证明：可靠性 (Soundness) 

问题：如果`SubsetSumSolver`算法结束后T_rem = 0，为什么说就代表了算法成功地找到了一组元素`S_solution`的组合？

#### **1. 定义循环不变量**

让我们来定义一个在算法的循环过程中始终成立的等式。

设 `T_rem(k)` 为算法在考察完前 `k` 个元素后的 `T_rem` 值。
设 `S_solution(k)` 为算法在考察完前 `k` 个元素后的 `S_solution` 集合。

我们要证明的**循环不变量**是：
$$T_{rem}(k) + \sum_{s \in S_{solution}(k)} s = T$$

T_rem的行为是初始化为T,然后不断的减去有可能的sᵢ,也就是  T-已选入解集的元素之和

所以这个等式表明，在循环的每一步之后，   **总目标T-已选入解集的元素之和** 加上 **已选入解集的元素之和**，结果永远等于**最初的总目标 `T`**,等式本身是显然成立的。

#### **2. 数学归纳法证明**

我们将通过数学归纳法来证明这个不变量在整个算法执行期间始终成立。

* **基准情况 (Base Case)(等价于递推式的最简单情况): `k = 0`**
    在循环开始之前（即考察了0个元素时）：
    * `S_solution(0)` 是空集 `[]`，所以其元素之和 `Sum(S_solution(0)) = 0`。
    * `T_rem(0)` 被初始化为 `T`。
    * 此时，不变量等式为：`T_rem(0) + Sum(S_solution(0)) = T + 0 = T`。
    * **结论**：在循环开始前，不变量成立。

* **归纳步骤 (Inductive Step)**
    **假设**在考察完第 `k-1` 个元素后，不变量成立。即：
    $$T_{rem}(k-1) + \sum_{s \in S_{solution}(k-1)} s = T$$
    现在，我们来分析算法在考察第 `k` 个元素 `sₖ` 时的两种情况：

    * **情况一：解集 `S_solution` 加入 `sₖ`  之后**
        根据算法的决策逻辑，这会发生。此时，状态更新如下：
        * `S_solution(k)` = `S_solution(k-1) ∪ {sₖ}`，因此 `Sum(S_solution(k)) = Sum(S_solution(k-1)) + sₖ`。
        * `T_rem(k)` = `T_rem(k-1) - sₖ`。

        我们将新状态代入不变量等式的左侧：
        `T_rem(k) + Sum(S_solution(k))`
        `= (T_rem(k-1) - sₖ) + (Sum(S_solution(k-1)) + sₖ)`
        `= T_rem(k-1) + Sum(S_solution(k-1))`
        根据我们的归纳假设，上式的结果等于 `T`。
        **因此，在这种情况下，不变量在第 `k` 步之后依然成立。**

    * **情况二：`sₖ` 未被加入解集 `S_solution`**
        在这种情况下，状态更新如下：
        * `S_solution(k)` = `S_solution(k-1)`，因此 `Sum(S_solution(k)) = Sum(S_solution(k-1))`。
        * `T_rem(k)` = `T_rem(k-1)`。

        我们将新状态代入不变量等式的左侧：
        `T_rem(k) + Sum(S_solution(k))`
        `= T_rem(k-1) + Sum(S_solution(k-1))`
        根据我们的归纳假设，上式的结果等于 `T`。
        **因此，在这种情况下，不变量在第 `k` 步之后也依然成立。**

* **结论**
    通过数学归纳法，我们证明了这个循环不变量 `T_rem(k) + Sum(S_solution(k)) = T` 在算法的每一次迭代后都始终保持成立。


#### **3. 推论**

当算法遍历完所有 `n` 个元素并终止时，该不变量依然成立。设 `T_rem_final` 和 `S_solution_final` 为最终状态。我们有：
$$T_{rem\_final} + \sum_{s \in S_{solution\_final}} s = T$$
此时，算法的返回逻辑是检查 `T_rem_final` 是否等于 `0`。如果 `T_rem_final = 0`，我们可以将它代入上述已被证明的等式中：
$$0 + \sum_{s \in S_{solution\_final}} s = T$$
$$\sum_{s \in S_{solution\_final}} s = T$$
**证明完毕。** 这表明，当且仅当算法终止时 `T_rem` 为0，我们构造的解集 `S_solution` 的元素之和才精确地等于原始目标 `T`。

因此算法结束时如果 T_rem 变成了 0，我们就能确定 Sum(S_solution) 一定等于 T


#### 证明:完备性 (Completeness)

问题：如果问题本身真的存在一个解，那么算法结束时 T_rem 为什么必然会等于 0(循环结束后不变量能推出算法的正确结果)?


**待证命题**：对于任何一个确实存在解的子集和问题实例 `(S, T)`，报告中描述的 `SubsetSumSolver` 算法保证会终止，并返回“是”（即最终 `T_rem = 0`）。

**采用反证法证明**：


1.  **做出反证假设**
    假设待证命题为假。即，**存在**一个最优解 `S*`（其所有元素之和为 `T`），但 `SubsetSumSolver` 算法在执行后**失败**了，最终返回“否”（即算法终止时 `T_rem > 0`）。

2.  **分析失败的必然原因**
    如果算法最终结果不正确，那么在其按降序遍历元素的执行过程中 ，必然至少有一次做出了“错误”的决策。我们可以定位到算法**第一次**犯错的时刻。这个错误必然是：
    * 算法**没有选择**一个本应属于最优解 `S*` 的元素。我们称这个被错误“跳过”的元素为 `s*`。

    在考虑 `s*` 之前，所有比 `s*` 大的元素都已被正确处理。

3.  **分析算法做出错误决策的条件**
    根据 `SubsetSumSolver` 的决策逻辑，算法之所以会“跳过”`s*`，是因为未能满足其 `if` 判断条件。该条件为 `sᵢ <= T_rem` 且 `T_rem - sᵢ <= MaxSubsetSum(S_rem)` 。

    分析这个条件对于 `s*` 不成立的原因：
    * **对于 `s* <= T_rem`**：在处理 `s*` 时，`T_rem` 的值等于 `T` 减去所有已被选中的、比 `s*` 更大的 `S*` 成员之和(由S降序保证)。
    
    因此，`T_rem` 的值恰好等于 `s*` 加上所有比 `s*` 小的 `S*` 成员之和。
    
    即   
    
    $$T_{rem} - s^* =  \sum_{x \in S^*, x < s^*} x$$ 
    
    所以，`T_rem >= s*` 必然成立。

    * **因此，决策失败的唯一原因**，只能是算法在那个时刻判断出：
        $$T_{rem} - s^* > \text{MaxSubsetSum}(S_{rem})$$

4.  **推导矛盾**
    来分析这个不等式的两端：
    * **不等式左端 `T_rem - s*`**：根据上面的分析，这个值等于**最优解 `S*` 中，所有比 `s*` 小的元素的和**。
    * **不等式右端 `MaxSubsetSum(S_rem)`**：这个值是算法当前“待考察”的元素集合 `S_rem` 所能构成的最大子集和。
    * 最优解 `S*` 中那些比 `s*` 小的元素，必然是 `S_rem` 集合的一个子集。因此，从 `S_rem` 所能构成的最大子集和，必然大于或等于其任何一个子集的和。所以，逻辑上必然成立：
    
        $$\text{MaxSubsetSum}(S_{rem}) \geq \sum_{x \in S^*, x < s^*} x$$

        使用之前得到的等式,也即是：

        $$\text{MaxSubsetSum}(S_{rem}) \geq T_{rem} - s^* $$
    此时，矛盾出现：
    * 我们的**假设**（算法失败）导出了结论：`T_{rem} - s* > MaxSubsetSum(S_{rem})`。
    * 而**逻辑推演**得出的必然结论是：`T_{rem} - s* <= MaxSubsetSum(S_{rem})`。

    同一个表达式不可能同时大于并小于等于另一个表达式。数学矛盾产生。

5.  **得出结论**
    产生矛盾的根源在于我们第一步的假设。因此，“存在一个解，但算法没有找到它”这个假设是错误的。

    故待证命题为真：对于任何存在解的子集和问题实例，`SubsetSumSolver` 算法保证能找到解，并以 `T_rem = 0` 的状态终止。

此证明确保了 `SubsetSumSolver` 算法的决策逻辑足够**完备**，不会遗漏任何存在的解。


所以，`SubsetSumSolver` 算法具有**完全正确性**。


**第三步：复杂度分析与矛盾推导**

* **复杂度**：`SubsetSumSolver` 算法对集合 `S` 中的 `n` 个元素进行了一次遍历。在每次循环中，它调用了一次多项式时间的 `MaxSubsetSum` 函数。因此，整个 `SubsetSumSolver` 算法的运行时间是多项式的。
* **矛盾**：我们已经设计出一个多项式时间算法 (`SubsetSumSolver`)，它能准确地解决 NP-complete 的“子集和问题”。这直接导出了 P=NP 的结论，与计算复杂性理论中 P≠NP 的基本假设相矛盾。

**第四步：结论**

导致上述矛盾的根源在于我们在第一步中的假设——即“`CARD_GAME_OPT` 存在多项式时间解法”。因此，该假设必须是错误的。

**所以，卡牌游戏优化问题 `CARD_GAME_OPT` 是 NP-hard 的。**



**结论2：卡牌游戏得分的泛化版本最大化问题是 NP-hard 的。**
